# 랭킹 종목 Redis 캐싱 정책

## 적용 대상

이 정책은 상승종목, 하락종목, 거래량 급등 종목, 거래대금 상위 종목, 신고가/신저가 근접 종목 등 특징주 랭킹 목록 캐시에 적용한다.

- API: `GET /api/v1/featured-stocks`
- Reader: `TopRankingReader`
- 외부 원천: KIS 국내주식 랭킹 API
- Redis key 형식: `ranking-stocks:{yyyyMMdd}:{topic}:{limit}`

## 기본 원칙

- 랭킹 캐시 날짜는 단순 달력 날짜가 아니라 KRX 거래일 기준으로 계산한다.
- 주말과 공휴일 날짜를 Redis key 날짜로 사용하지 않는다.
- 거래일 판정은 `TradingCalendarService`를 사용한다.
- `TradingCalendarServiceImpl`은 주말과 `market_holiday` 테이블을 기준으로 거래일을 판정한다.
- KRX 랭킹은 시장 코드 `"KRX"` 기준으로 계산한다.

## 캐시 날짜 정책

### 거래일

- `08:25` 이전에는 직전 거래일 날짜를 key 날짜로 사용한다.
- `08:25` 이상에는 당일 거래일 날짜를 key 날짜로 사용한다.

### 비거래일

- 토요일, 일요일, 공휴일에는 직전 거래일 날짜를 key 날짜로 사용한다.
- 예: 토요일과 일요일 요청은 금요일이 거래일이었다면 금요일 날짜 key를 사용한다.

## TTL 정책

### 거래일 장중

- `08:30` 이상 `18:00` 이전에는 10초 TTL을 사용한다.
- 장중 랭킹 변동을 반영하기 위한 짧은 캐시다.

### 거래일 장전 전환 구간

- `08:25` 이상 `08:30` 이전에는 캐시를 비활성화한다.
- 이 구간은 전일 랭킹과 당일 랭킹의 경계가 모호하므로 fresh fetch를 우선한다.

### 거래일 장외

- 장 마감 이후에는 다음 거래일 `08:25`까지 캐시한다.
- `08:25` 이전 새벽에는 당일 `08:25`까지 직전 거래일 캐시를 유지한다.

### 비거래일

- 다음 거래일 `08:25`까지 캐시한다.
- 주말 동안에는 직전 거래일 key를 재사용하고, 다음 거래일 장전 컷오프에서 만료되도록 한다.

## 예시

- 금요일 `17:00`: `ranking-stocks:금요일:...`, TTL 10초
- 금요일 `19:00`: `ranking-stocks:금요일:...`, TTL 다음 거래일 `08:25`까지
- 토요일 `10:00`: `ranking-stocks:금요일:...`, TTL 월요일 `08:25`까지
- 일요일 `10:00`: `ranking-stocks:금요일:...`, TTL 월요일 `08:25`까지
- 월요일 `08:00`: `ranking-stocks:금요일:...`, TTL 월요일 `08:25`까지
- 월요일 `08:26`: 캐시 비활성화, fresh fetch
- 월요일 `09:00`: `ranking-stocks:월요일:...`, TTL 10초

## 금지 사항

- `LocalDate.now()` 또는 `minusDays(1)`만으로 랭킹 캐시 날짜를 결정하지 않는다.
- 주말/공휴일 날짜가 포함된 `ranking-stocks:{yyyyMMdd}:...` key를 새로 만들지 않는다.
- 거래일 판단 로직을 `TopRankingReader`에 중복 구현하지 않는다.
- `TradingCalendarServiceImpl`의 주말/휴일 정책과 다른 별도 휴장일 규칙을 랭킹 캐시에 두지 않는다.

## 변경 시 확인 사항

- 랭킹 캐시 정책 변경 후 `./gradlew --no-daemon compileJava`를 실행한다.
- 주말, 공휴일, 거래일 `08:25`, `08:30`, `18:00` 경계 조건을 함께 점검한다.
- `market_holiday` 데이터가 누락되면 공휴일은 거래일로 판단될 수 있으므로 휴일 seed/migration 상태를 확인한다.
