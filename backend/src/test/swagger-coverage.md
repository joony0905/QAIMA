# Swagger 엔드포인트별 검증 추적표

작성일: 2026-09-25. 저장 명세 123개 작업. `SwaggerInventoryTest`는 reflection으로 현재 Controller 매핑과 명세 일치를 검증했습니다. 아래 구현 연결은 `tools/swagger_inventory.py`가 정적으로 추출한 검토 보조 자료입니다. 생성자 의존성 전체가 해당 메서드에서 실행된다는 뜻은 아닙니다.

현재123개 작업 모두 아래에 부분 업무 검증 근거가 있습니다. PARTIAL은 관련 파일/분기/전체 흐름의 완료가 아니며 실제 연동 NOT_RUN도 그대로 남깁니다. 종목 동기화는 실제 필터+handler 결합 검사에서 관리자 전용 명세와 달리 USER도 실행해 `SYNC-AUTH-001`로 실패했습니다. 기존 경로규칙/sentinel 보안 검사의 PASS를 권한 적정성 완료로 해석하지 않습니다.

`ApiSecurityMatrixTest`의 123 × 3 접근제어 검사는 PASS입니다. 실제 SecurityConfig·JwtAuthFilter를 사용하고 JWT provider와 최종 handler는 mock/sentinel입니다. 개별 비즈니스 흐름과 실제 연동의 완료를 뜻하지 않습니다. 사전 HTTP는 Repository mock, Feature1 흐름은 하위 Service mock 범위입니다. 사전 검색·자동완성·별칭·관리자 CRUD의 service fixture 검증을 추가했으나 실제 SQL·권한과 업무 handler 결합은 남았습니다.

Feature3의브라우저측추가검증은 [Chrome15개](../../../frontend/tests/browser-portfolio-flow.md)입니다. `/api/v1/portfolios/me/default` GET/PUT, `/api/v1/feature3/overlay-cache/preview` POST, `/api/v1/feature3/analysis` POST의화면입력·직렬화·합성응답처리를확인했습니다. 실제Spring과연결하지않았으므로아래실제연동상태를PASS로바꾸지않습니다.

Feature1의 [Chrome10개검사](../../../frontend/tests/browser-feature1-flow.md)는종목/캔들/재무·관심종목POST/DELETE·분석POST·잔액GET의화면요청과합성응답처리를검사했습니다. 실제Spring과연결한E2E가아니며아래실제연동상태와구분합니다.

리포트2경로·포트폴리오2경로는 [프로젝트 밖 복사본의 격리 MySQL 검증](isolated-service-jpa-copy.md)으로 Controller 메서드 직접 호출→실제 Service→JPA/DB의 일부 흐름을 추가 확인했습니다. 실제 HTTP 바인딩·보안필터/JWT와 브라우저까지 연결한 PASS는 아닙니다.
